# v0.5.0

## Highlights
- **Guardrails** – Secondary signals now default to the options flow. Dangerous intents enforce
  the updated confirmation paths and telemetry tokens, reducing accidental unlocks.
- **Intent configuration** – The adapter receives the new `intents` payload so structured hints
  stay synchronized between YAML, the options flow, and the FastAPI service.
- **Adapter** – Requests and responses are validated end-to-end with schema upgrades. Follow the
  adapter deployment guide to roll out the new signature checks safely.
- **Qdrant** – Fresh ingestion scripts enrich payload metadata so the adapter retrieves higher
  fidelity context from both `ha_entities` and `plex_media` collections.

## Migration summary
- Guardrail defaults moved from YAML to options. Visit the integration options UI and confirm the
  **Dangerous intents** and **Intent thresholds** sections are configured as expected.
- Custom adapters must accept the additional `intents` field in request bodies.
- Update automations that referenced `guardrails.secondary_signals.voice_profiles`; they now rely
  on dynamic telemetry tokens.
- Replace uses of `scripts/bootstrap_qdrant.py` with `scripts/ingest_entities.py` and
  `scripts/ingest_plex.py`, then re-run both to populate the expanded payload schema.

## Release checklist for maintainers
1. Run `pytest` to confirm the documentation guardrails and integration tests pass.
2. Bump the version in `pyproject.toml`, `custom_components/entangledhome/manifest.json`, and
   `entangledhome_assistant.egg-info/PKG-INFO` (already done for this release).
3. Commit the changes and create the annotated tag:
   ```bash
   git tag v0.5.0
   git push origin v0.5.0
   ```
4. Publish the release. The GitHub workflow in `.github/workflows/release.yml` will create notes for
   the tag automatically.
